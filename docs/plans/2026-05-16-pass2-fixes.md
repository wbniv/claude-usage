### 5. `gnome-extension/extension.js` — fix count column alignment (code quality)

In `formatRows()`, compute a shared `maxCol2` width across all meters so count strings like
`"10/15"` (5 chars) don't break alignment with `"100%"` (4 chars).

Replace:
```javascript
// in the count branch:
const col2 = `${m.count}/${m.total}`.padStart(4);
// in the pct branch:
const col2 = `${pct}%`.padStart(4);
```

With a pre-computed `maxCol2` before the loop:
```javascript
const maxCol2 = Math.max(4, ...meters.map(m =>
    (m.count !== undefined && m.total !== undefined)
        ? `${m.count}/${m.total}`.length
        : `${m.pct ?? 0}%`.length));
```
Then both branches use `.padStart(maxCol2)`.

### 7. `server/usage-server.py` — defend against `_timestamp: 0` (residual from pass-2 note)

If the extension ever sends `_timestamp: 0`, the server currently passes it through
unchanged. The GNOME extension then computes an enormous age and fires the stale-data
warning. Fix: treat 0 the same as missing — fall back to server time.

**Add `import time`** to the import line:
```diff
-import json, os, subprocess, sys
+import json, os, subprocess, sys, time
```

**Change the timestamp normalisation block** to use `not body.get(...)` so that both the
missing-key case and the zero-value case are handled the same way:
```diff
-        if '_timestamp' not in body:
-            ts = body.pop('timestamp', None)
-            body['_timestamp'] = int(ts / 1000) if ts else 0
+        if not body.get('_timestamp'):
+            ts = body.pop('timestamp', None)
+            body['_timestamp'] = int(ts / 1000) if ts else int(time.time())
```

Result: missing → server time; `_timestamp: 0` → server time; normal `_timestamp: <epoch-s>` → unchanged.
