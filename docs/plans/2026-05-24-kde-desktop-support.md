# Add KDE Desktop Support

## Context

`claude-usage` currently supports only GNOME Shell (extensions 45–50). The project displays Claude.ai weekly usage as a panel indicator with a popup breakdown and a dock icon with concentric rings. A KDE user on Plasma 5.27+ has no panel indicator — the only thing that currently "works" is the dock icon (generated by `generate-icon.py`, which writes to `~/.local/share/icons/hicolor/` and falls back to hardcoded defaults when GSettings is unavailable).

This plan adds a **KDE Plasma plasmoid** — a native QML applet that shows the same data as the GNOME extension — alongside the existing GNOME extension. It also decouples `generate-icon.py`'s config read from GSettings so dock-icon colors and thresholds work correctly on KDE.

---

## Implementation Plan

### 1. Neutral config file for `generate-icon.py`

`generate-icon.py` currently reads colors/thresholds from `Gio.Settings` (GSettings). On KDE this schema is absent and it falls back silently to hardcoded defaults — dock icon rings use wrong colors. Add a fallback chain to `load_config()`:

1. `~/.config/claude-usage/config.json` (written by KDE plasmoid on config save)
2. GSettings `org.gnome.shell.extensions.claude-usage` (GNOME only — may throw)
3. Hardcoded `DEFAULTS`

The JSON schema mirrors the gschema keys (same names, same defaults). On GNOME, nothing changes because the JSON file won't exist and GSettings succeeds as before.

File to modify: `server/generate-icon.py` — modify `load_config()` to attempt JSON read before the existing `Gio.Settings` try-block.

### 2. KDE Plasmoid (`kde-plasmoid/`)

New directory structure:

```
kde-plasmoid/
  metadata.json                        # Plasma 5.27+ / Plasma 6 manifest
  metadata.desktop                     # Legacy Plasma 5 manifest (< 5.27)
  contents/
    ui/
      main.qml                         # Root PlasmoidItem; Timer; data loading
      CompactRepresentation.qml        # Panel label (e.g. "72%") with color
      FullRepresentation.qml           # Popup: status line + meter rows
      MeterRow.qml                     # Reusable component: label + bar + reset
    config/
      config.qml                       # Declares config pages
      main.xml                         # KConfig schema (thresholds, colors)
    ui/config/
      ConfigGeneral.qml                # Settings UI (sliders + color pickers)
```

#### Data loading (`main.qml`)
- `Timer { interval: 30000; repeat: true }` polls `~/.cache/claude-usage/usage.json`
- Read via async `XMLHttpRequest` with `file://` URL: `StandardPaths.HomeLocation + "/.cache/claude-usage/usage.json"`
- Parses same JSON schema as GNOME extension (fields: `meters[]`, `status`, `last_update`)
- Exposes `usageData` property and `topMeter` computed property for compact view
- Also fires once on component completion (`Component.onCompleted`)

#### Compact representation (`CompactRepresentation.qml`)
- `PlasmaComponents3.Label` showing the selected meter's percentage (e.g. `"72%"`)
- Text color derived from pacing calculation matching `extension.js` lines ~180–200:
  ```
  pacing = pct / (elapsed_mins / period_mins)
  color = pacing >= threshCrit ? criticalColor : pacing >= threshWarn ? warningColor : normalColor
  ```
- Small Anthropic star icon to the left (reuse `gnome-extension/icons/claude-22.png`)
- Mouse wheel cycles through meters (same behaviour as GNOME extension)

#### Full representation (`FullRepresentation.qml`)
- Status bar at top (data age; "Anthropic degraded" if `status ≠ ok`)
- `Repeater` over `meters[]` → `MeterRow.qml` for each meter
- `MeterRow.qml`: label | percentage text | filled/unfilled bar (`Rectangle` widths proportional to pct) | reset countdown
- "Open Usage Page" link via `Qt.openUrlExternally("https://claude.ai/settings/usage")`
- Radio buttons to choose which meter appears in panel (writes to `Plasmoid.configuration.panelMetric`)

#### Config (`main.xml` + `ConfigGeneral.qml`)
KConfig schema with the same 13 keys as the gschema (thresholds + colors for normal/warning/critical panel label and bars) **plus `popupFontFamily` string (default `"monospace"`)**. Defaults identical to gschema defaults.

For the font family setting, use Qt's `FontDialog` (Qt 6 / Plasma 6) or `Qt.FontDialog` rather than a plain `TextField`. Open it via a `Button` that shows the current font name; on `accepted`, write `font.family` to the KConfig key and to `~/.config/claude-usage/config.json` so `generate-icon.py` can read it (parity with the GNOME prefs round-trip). This matches the GNOME `Gtk.FontDialogButton` approach.

On config save, `ConfigGeneral.qml` writes `~/.config/claude-usage/config.json` so `generate-icon.py` picks up user-customized dock ring colors.

### 3. Installer changes (`install.sh`)

Add KDE detection before the existing GNOME install block:

```bash
if echo "${XDG_CURRENT_DESKTOP:-}" | grep -qi "KDE"; then
    kde_install
else
    gnome_install   # existing path, unchanged
fi
```

`kde_install()`:
1. `rsync -a kde-plasmoid/ ~/.local/share/plasma/plasmoids/org.indri.claude-usage/`
2. Print restart notice: `kquitapp5 plasmashell && kstart5 plasmashell` (Plasma 5) or `kwin_wayland --replace` note for Plasma 6

---

### 4. Packaging changes

**`packaging/control`:**
- Change `Depends: gnome-shell (>= 45)` → `Recommends: gnome-shell (>= 45) | plasma-desktop`
- Add plasmoid files to the install manifest in `build-deb.sh`:
  - Source: `kde-plasmoid/`
  - Destination: `/usr/share/plasma/plasmoids/org.indri.claude-usage/`

**`packaging/postinst`:**
- Detect `$XDG_CURRENT_DESKTOP` and call the right enable step (GNOME: `gnome-extensions enable`; KDE: `plasmapkg2 --install` or direct copy already done by package)

---

### 5. `Taskfile.yml` additions

```yaml
kde-install:
  desc: Install KDE plasmoid for the current user
  cmds:
    - rsync -a kde-plasmoid/ ~/.local/share/plasma/plasmoids/org.indri.claude-usage/
    - echo "Restart Plasma shell to load the widget"

kde-uninstall:
  desc: Remove KDE plasmoid
  cmds:
    - rm -rf ~/.local/share/plasma/plasmoids/org.indri.claude-usage
```
